# แบ่งยอดบริการตามขั้นตอน

สัดส่วนขึ้นอยู่กับประเภทบริการเท่านั้น หมาและแมวใช้สัดส่วนเดียวกันสำหรับบริการประเภทเดียวกัน

ก่อนใช้เวอร์ชันนี้กับฐานข้อมูลเดิม ให้รัน `supabase/migrations/20261101_grooming_stage_allocation.sql` ใน Supabase SQL Editor ก่อน deploy แอป โดย migration เพิ่ม `bookings.grooming_allocation` และไม่แก้รายการย้อนหลัง

ในหน้าสร้างคิว แก้ไขคิว หรือรับชำระเงิน เลือกพนักงานผู้ให้บริการ 1–2 คน แล้วเลือกรูปแบบบริการ:

- อาบน้ำอย่างเดียว (หมาและแมว): เตรียมตัว 10%, อาบน้ำ 30%, เป่าขน/หวีขน/เก็บงาน 60%
- อาบน้ำพร้อมตัดขน (หมาและแมว): เตรียมตัว 5%, อาบน้ำ 20%, เป่าขน 30%, ตัดขน/เก็บทรง 45%

บริการอื่นที่ยังไม่มีกติกาสัดส่วน ให้เลือก “บริการอื่น / แบบเดิม” เพื่อใช้การแบ่งยอดทั้งบริการต่อไป

แต่ละขั้นตอนเลือกให้พนักงานหลักทำ พนักงานร่วมงานทำ หรือทำร่วมกันได้ ถ้าทำร่วมกันจะแบ่งสัดส่วนของขั้นตอนนั้นคนละครึ่ง หน้าจอแสดงชื่อผู้ทำโดยไม่แสดงเปอร์เซ็นต์

## หลายตัวในบิลเดียว

ในหน้ารับเงินของบิลอาบน้ำ/ตัดขนเก่า ใช้ส่วน “จัดการชื่อสัตว์เลี้ยงในบิล” เพื่อเลือกสัตว์เลี้ยงของลูกค้าเดิม กำหนดชื่อใหม่ หรือเพิ่มตัวที่สอง ถ้าชื่อเดิมรวมด้วย `/` ให้กด “แยกชื่อที่คั่นด้วย /” แล้วตรวจแต่ละช่อง กด “บันทึกรายชื่อในบิล” ก่อนระบุราคาและผู้ทำรายตัวด้านล่าง ใช้ได้ทั้งบิลที่ยังค้างเงินและบิลที่รับครบแล้ว โดยบิลรับครบมีปุ่มบันทึกผู้ให้บริการได้โดยไม่รับเงินเพิ่ม

การกำหนดชื่อใหม่จะใช้สัตว์เลี้ยงของลูกค้าที่ตรงกันหรือเพิ่มรายการใหม่ แล้วเปลี่ยนเฉพาะตัวที่ผูกกับบิลนั้น ไม่เปลี่ยนชื่อสัตว์เลี้ยงเดิมในบิลอื่น การแก้รายชื่อไม่แก้ยอดบิล มัดจำ หรือประวัติรับเงิน และเก็บราคา/ผู้ทำเดิมไว้ หากบิลที่เคยระบุรายตัวเพิ่มตัวที่สอง จะเริ่มราคาของตัวที่เพิ่มที่ 0 เพื่อรักษาฐานยอดเดิม ให้ตรวจและแก้ราคาแต่ละตัวให้ถูกต้องก่อนบันทึกผู้ทำ ระบบยังตรวจรายชื่อของลูกค้า คิวซ้อนสำหรับคิวที่กำลังดำเนินการ และการแก้ไขบิลพร้อมกันก่อนบันทึก

การ import ข้อความลงคิวจะแยกชื่อด้วย `/` (รวมถึง `／`) เช่น `ชื่อน้อง : น้องโอ๊ะ/อุง` เป็นชื่อน้องตัวแรก `น้องโอ๊ะ` และตัวที่สอง `อุง` ตัดช่องว่างข้างเครื่องหมาย แต่ไม่แยกช่องว่างภายในชื่อ แสดงชื่อแยกให้ตรวจในฟอร์มก่อนบันทึก หากเกิน 2 ตัว ชื่อซ้ำ หรือเว้นชื่อข้างใดข้างหนึ่ง จะให้แก้ข้อความแทนการตัดชื่อทิ้ง

หากพบสัตว์เลี้ยงเดิมทั้งคู่ ระบบจะเลือกทั้งคู่ให้ หากยังมีตัวที่ไม่พบ จะตรวจข้อมูลของเจ้าของและใช้รายการเดิมที่ชื่อตรงกันก่อนสร้างเฉพาะตัวที่ขาด เมื่อสร้างรหัสสัตว์เลี้ยงจริงแล้ว ระบบผูกกลับไปยังราคาและผู้ทำของตัวนั้น ไม่บันทึกรวมเป็นชื่อเดียว ข้อมูลเก่าที่เก็บชื่อรวมไว้ยังไม่ถูกแก้อัตโนมัติ เบอร์โทรหลายเบอร์ในข้อความใช้เบอร์แรกเป็นเบอร์หลักและเก็บเบอร์เพิ่มเติมในหมายเหตุคิว

บิลที่มีสัตว์เลี้ยง 2 ตัว (ตามจำนวนที่ระบบจองรองรับปัจจุบัน) จะแสดงปุ่มชื่อให้สลับเลือกตัว แต่ละตัวมีราคาบริการ ประเภทบริการ พนักงานหลัก พนักงานร่วมงาน และผู้ทำแต่ละขั้นตอนของตัวเอง พนักงานของแต่ละตัวเลือกต่างกันได้ สลับตัวแล้วข้อมูลที่กรอกยังคงอยู่

กรอกราคาของแต่ละตัวเป็นจำนวนเงินบาทเต็มบาท โดยยอดรายตัวรวมกันต้องตรงกับยอดบิล ระบบตรวจทั้งในฟอร์มและฝั่งเซิร์ฟเวอร์ก่อนบันทึก รวมถึงตรวจว่าสัตว์เลี้ยงอยู่ในบิลจริงและพนักงานที่เลือกใช้งานได้

ตัวอย่าง โมจิ 900 บาทและลูน่า 600 บาท รวมบิล 1,500 บาท หากรับมัดจำ 300 บาท จะนำยอดรับจริง 180 บาทไปแบ่งตามงานของโมจิ และ 120 บาทตามงานของลูน่า จากนั้นรวมฐานยอดตามพนักงานก่อนคิดค่าคอมเดิม จึงไม่คิดยอดบริการซ้ำหรือหารยอดเท่ากันทุกตัว

ข้อมูลรายตัวใช้รูปแบบ `{ version: 2, pets: [{ petId, amount, performedById, secondaryPerformedById, allocation }] }` ในคอลัมน์ `bookings.grooming_allocation` เดิม จึงไม่ต้องเพิ่มคอลัมน์หรือรัน migration ใหม่หากมีคอลัมน์นี้แล้ว รายการเก่ายังอ่านและคำนวณด้วยกติกาเดิมจนกว่าจะบันทึกข้อมูลรายตัว การแก้ราคาและผู้ทำของรายการเก่าจะมีผลต่อรายงานย้อนหลังของยอดรับเงินที่ผูกกับบิลนั้นด้วย

ตัวอย่างงานอาบน้ำอย่างเดียว 1,000 บาท: คน A เตรียมตัวและอาบน้ำ ส่วนเป่าขนทำร่วมกัน A/B จะได้ฐานยอด A = 700 บาท และ B = 300 บาท จากนั้นนำฐานยอดสะสมแต่ละคนไปคิดค่าคอมแบบขั้นบันไดเดิม (3%, 5%, 8%, 10%) สัดส่วนขั้นตอนเป็นการแบ่งฐานยอดบริการ ไม่ใช่อัตราค่าคอมที่จ่ายทันที

รายงานใช้ยอดรับเงินจริงในช่วงวันที่ที่เลือก รวมถึงยอดมัดจำที่ลงเป็นรายได้บริการตามระบบเดิม ไม่ใช้ราคาจองซ้ำกับยอดรับเงินจริง และไม่ปัดเศษระหว่างแบ่งฐานยอด

รายการเก่าที่ไม่มีข้อมูลขั้นตอนยังแบ่งยอดทั้งบริการตามเดิม (1 คนเต็มยอด / 2 คนคนละครึ่ง) สามารถแก้คิวเพื่อระบุขั้นตอนได้ การแก้ขั้นตอนของคิวมีผลกับรายงานของยอดรับเงินที่ผูกกับคิวนั้น การจัดการยอดที่ยังไม่ระบุพนักงานยังใช้กติกาเดิม
